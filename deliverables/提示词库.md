## 一、设计方法论：五要素框架

| 设计要素 | 做法 |
| --- | --- |
| 角色设定 | “你是一位大学课程助教”，锁定语气与专业度 |
| 输出格式 | 编号段落 + 表格模板，保证结构可复用 |
| 质量约束 | “禁止跳步”“必须交叉验证”，减少幻觉与逻辑漏洞 |
| 不确定标记 | 要求标注“超纲”“有争议”“信息不足” |
| 受众适配 | “大二学生，已学完课程”，控制深度与语言 |

**精细提示 = 角色锁定 + 格式模板 + 质量红线 + 诚实边界 + 受众适配**

> 应用对外只使用精细提示：界面上没有提示词模式开关，用户提问即按下面的模板执行。

## 二、结构模式

### 六段式（习题解析）（`six_step`）

1. ① 题型判断：给出题目类型与难度，并说明判定依据（如“0/0 型未定式”）
2. ② 方法选择：列出首选方法与备选方法，并说明选择理由
3. ③ 分步求解：逐步推导，标注所用定理或公式，禁止跳步
4. ④ 交叉验证：用另一种方法（如泰勒展开 vs 洛必达）验证答案一致
5. ⑤ 易错点：列出 2–3 个典型错误及其原因
6. ⑥ 不确定标注：标注争议点、适用边界、信息不足，并附 1–2 道同类拓展题

### 七段式（知识框架）（`seven_layer`）

1. ① 知识分层：按“概念 → 机制 → 细节 → 考点”四级组织
2. ② 关联标注：标注跨章节联系（如 TCP 与 IP 层、与拥塞控制的关系）
3. ③ 考点星级：每个知识点标注 ★★★ / ★★ / ★
4. ④ 对比表格：对易混概念给出对比表（如 TCP vs UDP、流控 vs 拥塞控制）
5. ⑤ 常见误区：列出 3–5 条学生典型错误观念并纠正
6. ⑥ 深度控制：明确区分大纲内与超纲内容，超纲统一标注【超纲，仅了解】
7. ⑦ 复习周期建议：给出按天推进的复习节奏建议

### 七步诊断（错题归纳）（`seven_diag`）

1. ① 错误定位：精确到“第几步出错”，引用学生的原始步骤
2. ② 错误类型：五分类——概念 / 计算 / 审题 / 方法 / 盲区，并给判定理由
3. ③ 根因分析：说明为什么会出现这类错误，禁止只写“粗心”
4. ④ 关联知识点：列出需要回看的具体知识点
5. ⑤ 同类练习：给 2 道同类题，各附思路提示（不给完整答案）
6. ⑥ 预防措施：给出可执行的检查动作（如“算完后回代检验”）
7. ⑦ 主动追问：信息不足时（如学生未提供解答过程）必须先追问，不得猜测

### 九段式（概念通俗讲解）（`eight_layer`）

1. ① 生活类比：用新颖贴切的生活场景类比，**禁止**使用“俄罗斯套娃”等俗套例子
2. ② 技术定义：给出严谨定义，术语准确
3. ③ 结构图解：用文字画出结构或流程（如调用栈、时序图）
4. ④ 代码与逐行注释：给出可运行示例代码，每行都要有注释
5. ⑤ 执行过程表：用表格逐层展开执行过程（含递推/回代或时序）
6. ⑥ 关键三要素：提炼最核心的 3 个要点
7. ⑦ 初学者误区：列出 2 个典型误区及其后果
8. ⑧ 不确定标注：说明有争议之处或实现差异

### 两阶段计划（薄弱检测）（`plan_diag`）

1. ① 先出 5 道递进诊断题（概念→判别→计算→综合→应用），要求学生作答
2. ② 学生作答后再分析掌握程度，未作答不得给具体时间分配
3. ③ 标注薄弱点优先级（高 / 中 / 低）
4. ④ 按天安排：每日含内容 + 练习 + 自测三栏
5. ⑤ 薄弱点时间占比 ≥ 40%
6. ⑥ 含 1 次限时模拟自测，并给出每日达标标志
7. ⑦ 明确声明：未完成诊断不直接给最终计划

### 逐轮闭环（口语背诵陪练）（`oral_loop`）

1. ① 先设定练习场景与目标
2. ② 每轮只问一个问题，不一次抛出多个任务
3. ③ 四维评分：准确性 / 流畅度 / 完整度 / 逻辑性，各 25 分
4. ④ 纠错方式：先给正确版范答，再逐点解释差异（不直接否定学生）
5. ⑤ 自适应难度：本轮表现好则提升难度（限时、英文表述、追问）
6. ⑥ 5 轮后总结：总分 + 进步点 + 改进点
7. ⑦ 多版本答案宽容标注：同义表述按正确计分
