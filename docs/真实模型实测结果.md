> 复现命令：

## 一、事实幻觉 + 逻辑缺陷 对照测试（11 个用例）

测试对象：DeepSeek `deepseek-flash`　控制变量：同一模型、同一参数，仅改变提示词类型

| 对照组 | 幻觉率 | 逻辑错误率 | 合规率 | 结构完整度 | 不确定标记 | 教学价值 | 平均字数 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 粗放提示（基线） | 33%（2/6） | 0%（0/5） | 73% | 0.10 | 0.00 | 0.07 | 262 |
| 精细提示（生产） | **0%**（0/6） | 0%（0/5） | **100%** | **0.72** | **0.77** | 0.32 | 2023 |

### 关键发现

1. **事实幻觉率 33% → 0%**：粗放提示下，模型在「无来源的精确数据」类问题上出现编造
   （H1 教材例题数值、H6 教材页码/定理编号）；加入「不确定时必须声明、禁止编造出处」约束后，6 道题全部拒绝编造。
2. **逻辑错误率两版均为 0%**：与阶段三汇报中「粗放提示错误率约 65%」不同——
   该模型在条件推导、充要条件、方向性判断上本身已较稳健，提示词工程**没有**改变其逻辑正确性。
3. **提示词工程的真实增益在结构、透明度与诚实边界**：
   结构完整度 0.10 → 0.72（提升 0.62），主动的不确定标记 0.00 → 0.77，平均输出 262 → 2023 字。
4. **核心结论**：提示词工程的主要价值是「让输出**可预期、可复用、可信赖**」，
   而不是「让模型变聪明」——这一判断与阶段二汇报的结论一致，并在此得到了真实模型的量化支持。

### 与阶段三汇报的差异说明

| 维度 | 阶段三汇报（GPT-4o 等） | 本次实测（deepseek-flash） |
| --- | --- | --- |
| 粗放提示幻觉率 | 约 80% | 33% |
| 粗放提示逻辑错误率 | 约 65% | 0% |
| 精细提示幻觉率 | 约 20% | 0% |

差异原因：① 模型版本与厂商不同；② 粗放提示的构造方式不同
（本应用按阶段三描述采用"直接提问、不带任何约束"的基线，见 `ai_tutor/eval/cases.py`
中每个用例的 `coarse_prompt` 字段）。**汇报中的数字来自当时的实测，本表来自当前实测，
两者都保留，不做相互覆盖。**

## 二、同质化测试（同一任务表述变体重复 3 次）

| 对照组 | 重复度（综合） | 2-gram | LCS | 结构 | 结构完整度 | 平均字数 |
| --- | --- | --- | --- | --- | --- | --- |
| 默认精细提示 | 31% | 27% | 35% | 38% | 0.90 | 1798 |
| 加入反同质化约束 | **21%** | 19% | 23% | 0% | 0.75 | 2383 |

### 关键发现

1. **默认精细提示的重复度 31%，已接近 30% 的可接受线**，远低于阶段三汇报中
   「相似度 85%–90%」的观察——说明该模型在同一任务上本身就有较强的表达变化能力。
2. **反同质化约束有效**：加入「变换叙述风格 + 至少 2 种组织方式 + 不要套话」后，
   重复度进一步从 31% 降到 21%，同时平均输出变长（1798 → 2383 字），
   说明它确实换了组织结构，而不是把内容压短。
3. **注意**：第一次实测中出现过"反同质化后重复度反而升高"的情况，原因是当次请求
   触发了接口降级（见下文第三节）。这也说明**反同质化指令需要按模型调优，
   不能默认"加了就一定更好"**——程序会在报告中明确提示这种情况。

## 三、实测过程中发现并修复的工程问题

真实模型联调暴露了 4 个只有接真模型才会出现的问题，均已修复：

| # | 问题 | 影响 | 修复 |
| --- | --- | --- | --- |
| 1 | DeepSeek 在 JSON 模式下返回**大量前导空白** | 输出长度、相似度、质检指标全部失真 | `openai_compat.py` / `anthropic.py` / `qianfan.py` 统一 `strip()`；`quality_check` 再做一次归一化 |
| 2 | 模型以 **JSON 优先**返回（正文在 JSON 字符串里） | 段落标题检测失效、JSON 抽取失败 | 抽取器改用 `JSONDecoder.raw_decode`；质检增加「按本模块段落名匹配 + 允许退化匹配 + 【标记】证据」三条通路 |
| 3 | 粗放提示不含 "json" 字样时，`response_format=json_object` 被 DeepSeek 拒绝（HTTP 400） | 粗放对照组**静默降级**成离线模型，导致"标注为某模型、实际跑的是 mock"的数据失真 | ① 仅在提示词含 "json" 时才启用 JSON 模式；② 降级结果强制保留 `simulated=true`；③ 报告仅在**全部**对照组都来自离线模型时才标注"离线模拟" |
| 4 | 输出被 `max_tokens` 截断（表格与 JSON 不完整） | 结构分被误判为低 | `max_tokens` 提升到 8192；新增 `finish_reason=length` 的**截断告警**写入结果与界面 |

> 第 3 条是最值得记录的一条：如果没有"降级必须打标 + 报告按来源区分"的机制，
> 这类问题会直接产出**看起来合理但完全错误**的实验结论。

## 四、检测器的已知局限（必须人工复核）

自动判定器用「风险正则 + 断言语境 + 否定语境」三件套识别风险，实测中仍存在两类误判，
报告中会保留原始输出供人工复核：

1. **纠错引用被误判**：模型说「正确的方向是越大越小」时，句中同时含"越大""突跃"等字样，
   可能命中方向倒置的正则。已通过负向断言与否定词窗口大幅降低，但无法完全消除。
2. **极简回答无法判定**：如粗放提示下模型只回答「不是。」——既没有错误结论关键词，
   也没有正确结论关键词，判定器会返回"无法判定"，需要人工看原文。

因此本应用的定位是：**自动判定用于批量筛选与趋势对比，最终结论必须人工复核**；
涉及教材页码、文献 DOI、政策条文的输出一律要求标注「待核实」。

## 五、如何得到你自己的实测数据

```powershell
# 1) 配置 Key（三选一，环境变量优先级最高）
$env:DEEPSEEK_API_KEY="..."
$env:OPENAI_API_KEY="..."
$env:ANTHROPIC_API_KEY="..."

# 2) 建议把真实数据与离线基线分开存放
$env:AI_TUTOR_DATA_DIR="D:\project\data_real"

# 3) 指定模型执行
python -m ai_tutor risk run --kind pair        --model deepseek
python -m ai_tutor risk run --kind repetition  --model deepseek --rounds 3
python -m ai_tutor risk run --kind comparison  --models openai anthropic qianfan

# 4) 多模型横向对比（需要对应 Key）
python -m ai_tutor risk run --kind comparison
```

报告输出到 `data_real/reports/*.md` 与 `*.json`，逐条记录含**提示词原文与输出原文**。
