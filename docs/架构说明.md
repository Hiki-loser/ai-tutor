> 大学生期末复习 AI 答疑助手 · 第二组：李明轩　韩武晋　郑志
> 本文档说明系统的分层设计、关键算法与设计取舍。

## 一、总体分层

```text
┌──────────────────────────────────────────────────────────────────────┐
│  入口层        CLI (cli.py)      Web UI (webapp.py + web/)            │
├──────────────────────────────────────────────────────────────────────┤
│  服务门面      AgentService (service.py)                              │
│                ── 统一 ask / ablate / run_risk / report / export       │
├──────────────────────────────────────────────────────────────────────┤
│  能力层        features/  M1 习题解析   M2 知识框架   M3 错题归纳       │
│                          M4 概念讲解   M5 薄弱检测   M6 口语陪练       │
│                features/base.py::quality_check  ← 自动化质检           │
├──────────────────────────────────────────────────────────────────────┤
│  提示词层      prompts/  ModuleSpec + 六种结构模式 + 五要素框架         │
├──────────────────────────────────────────────────────────────────────┤
│  模型层        llm/  registry(注册/降级) → router(任务路由)            │
│                      providers: openai-compat / anthropic / qianfan   │
│                               mock(离线)                              │
├──────────────────────────────────────────────────────────────────────┤
│  评测层        eval/  cases(用例+判定) metrics(量化) runner(执行)      │
├──────────────────────────────────────────────────────────────────────┤
│  持久层        storage.py (SQLite)   utils.py (文本/相似度算法)        │
└──────────────────────────────────────────────────────────────────────┘
```

**设计原则**

1. **单一事实来源**：六个模块的提示词只在 `prompts/modules.py` 定义一次，
   CLI / Web / 评测脚本 / 导出文档全部由它生成，不会出现"文档与代码不一致"。
2. **门面统一**：所有入口经 `AgentService`，保证"同一套提示词、同一套路由、同一套记录"，
   这是阶段三"控制变量法"要求的基础设施。
3. **失败可降级、结果可复现**：任何远端异常都退回内置离线模型并打标 `degraded`，
   应用永远可用；离线模型的输出可完全复现，便于课程演示与回归测试。
4. **零第三方依赖**：只用标准库，避免环境问题影响验收。

## 二、提示词层

### 2.1 五要素框架（阶段二方法论）

| 要素 | 做法 |
| --- | --- |
| 角色设定 | "你是一位大学课程助教"，锁定语气与专业度 |
| 输出格式 | 编号段落 + 表格模板，保证结构可复用 |
| 质量约束 | "禁止跳步""必须交叉验证" |
| 不确定标记 | 要求标注"超纲""有争议""信息不足" |
| 受众适配 | "大二学生，已学完课程" |

实现：`prompts/modules.py::COMMON_REDLINES` + `COMMON_UNCERTAINTY` +
每个模块自己的`redlines` / `uncertainty_rules`，由 `ModuleSpec.fine_prompt()` 拼装。

### 2.2 六种结构模式

| 模式 key | 标签 | 段落数 | 使用模块 |
| --- | --- | --- | --- |
| `six_step` | 六段式 | 6 | M1 |
| `seven_layer` | 七段式 | 7 | M2 |
| `seven_diag` | 七步诊断 | 7 | M3 |
| `eight_layer` | 九段式 | 8 | M4 |
| `plan_diag` | 两阶段计划 | 3 | M5 |
| `oral_loop` | 逐轮闭环 | 6 | M6 |

每个模式由 `sections`（段落名，用于质检比对）与 `requirements`（写进提示词的具体要求）组成。
`quality_check` 用 `sections` 计算**结构覆盖率**，形成"提示词要求 → 自动验收"的闭环。

### 2.3 提示词组装

```python
ModuleSpec.fine_prompt() 生成顺序：
  【角色】→【受众】→【任务】→【输出格式 + 逐条 requirements】
  →【格式补充】→【质量约束(redlines)】→【不确定标记要求】
  →【全局红线：禁止编造文献/数据/页码/政策条文】
  →【结构化输出：附 JSON】
```

`BaseFeature.build_prompt()` 固定注入**输出契约**（必须出现哪些【段落名】、
先正文后 JSON、禁止只输出 JSON），并放在提示词末位——实测这样能显著提高真实模型的
格式遵守率。应用对外**没有**提示词模式开关。

## 三、能力层（六大模块）

### 3.1 公共流程

```text
BaseFeature.ask()
  ├─ ensure_session()          创建/复用会话
  ├─ ctx.images_from()         图片统一为 ImagePart（校验格式/大小/数量）
  ├─ build_prompt()            模块精细提示 + 运行期约束 + 图片契约 + 输出契约
  ├─ history_messages()        注入最近 6 轮上下文（多轮模块）
  ├─ resolve_model()           用户指定 / 任务路由 / 默认
  ├─ resolve_vision_model()    含图片时切到支持视觉的模型
  ├─ client.chat()             带降级的统一调用（多模态 content parts）
  ├─ render_structured_answer() JSON 优先返回 → 可读分段文本
  ├─ quality_check()           规则化质检
  └─ storage.add_turn()        落库（提示词原文 + 输出原文 + 图片元信息 + 指标）
```

### 3.2 模块特有逻辑

| 模块 | 特有处理 |
| --- | --- |
| M1 | `preflight()` 题干完整性预检查；从结构化结果抽取 `answer` / `error_prone` / `extended` |
| M2 | 主题与受众注入；`to_outline_markdown()` 导出可直接使用的复习提纲 |
| M3 | 注入**错误类型五分类字典**；无学生解答时强制"先追问不猜错因"；输出 `error_type` |
| M4 | 注入**类比禁令**；检查输出是否仍出现被禁类比并给出 ⚠ |
| M5 | **状态机**：`diagnose`（只出题、声明不下发计划）→ `plan`（按天计划）；自动核对薄弱点占比 ≥40% |
| M6 | **轮次状态机**：维护 `rounds` 列表，规则化四维预评分 + 5 轮后总结；课程状态存 `sessions.meta` |

### 3.3 图片输入（多模态）

```text
用户图片（本地路径 / base64 / data URI / Web 上传）
  → ImagePart.coerce()      统一为 ImagePart（校验类型、大小、数量）
  → 挂到当前 user Message 的 images 上
  → OpenAI 兼容协议：content = [{type:text},{type:image_url,image_url:{url:data:...}}]
    Anthropic      ：content = [{type:text},{type:image,source:{type:base64,...}}]
  → 提示词追加【图片输入】契约：先识别图中题目/公式/图表/手写演算，
    识别不清处必须写进【不确定标注】，禁止凭猜测补全题目条件
```

设计要点：

1. **零依赖**：只用 `base64` + `pathlib`，不引入 Pillow 等图像库。
2. **模型自动切换**：`LLMClient.pick_vision_model()` 依次尝试「用户指定（且支持视觉）→
   默认模型（支持视觉）→ 任意可用视觉模型」；若都没有，则回退到内置离线模型并
   **如实声明无法识别图片内容**，既不报错也不编造。
3. **路径与 base64 的区分**：用「是否只含 base64 字母表且长度 ≥ 64」判定，
   避免把拼错的路径当作 base64 解码，从而给出难以理解的报错。
4. **落库**：`meta.images` 记录每张图的名称 / MIME / 字节数，`meta.vision` 标记本轮含图片。

### 3.4 JSON 优先返回的还原

实测 DeepSeek 在 JSON 模式下经常「只输出 JSON」。`render_structured_answer()`
会用结构化结果重建【段落名】正文用于展示与质检（并在 `meta.json_first` 打标），
原始 JSON 仍完整保存在 `turns.structured` 中，信息不丢失。

### 3.3 自动化质检 `quality_check`

对输出计算：

```text
has_table            等宽表格字符 / Markdown 表格
has_code             代码特征
has_numbered_steps   第N步 / ①-⑨
section_coverage     模块要求段落命中率（支持同义与退化匹配）
uncertainty_marks    未核实/无法确认/有争议/超纲/信息不足 ...
redline_hits         按结构模式逐条检查（含交叉验证、含考点星级、先诊断、每轮一问 ...）
structure_score      0.7×覆盖率 + 0.15×表格 + 0.15×编号步骤
honesty_score        不确定标记数量归一化
teaching_score       表格/代码/篇幅加权
overall              0.5×结构 + 0.25×诚实 + 0.25×教学
```

**这是规则化近似**，用于批量筛选与对照实验，不能替代人工评价。

## 四、模型层

### 4.1 统一结果对象

```python
@dataclass
class ChatResult:
    text, provider, model
    elapsed_ms, prompt_tokens, completion_tokens
    degraded: bool, degraded_reason: str     # 是否从远端降级
    simulated: bool                          # 是否离线模型产出
    structured: dict | None                  # JSON 模式抽取结果
```

`simulated` 与 `degraded` 会被写入数据库并在 CLI/Web 上显式标注，
避免把模拟数据伪装成真实模型表现。

### 4.2 失败降级

```text
LLMClient.chat()
  ├─ provider.available() == False  → 回退 mock，reason="未配置 API Key"
  └─ provider.chat() 抛异常        → 回退 mock，reason="<provider> 调用失败: ..."
```

### 4.3 任务路由

```python
detect_task(text):
  1) 高精度信号优先：doi / sci / 文献 / 出处 / 页码 / 政策 / 条文 /
     数据来源 / 统计年鉴 / 是否一定 / 能否推出 / 充要 / 反例 ...
  2) 否则按一般关键词计分
  3) 都不命中 → general
```

关键设计：**模块只作弱先验**。即使问题被分到 M2（知识框架），
只要文本含"DOI / 文献 / 页码"等信号，任务类型仍判为 `fact_check`，
从而路由到最保守的模型——避免格式指令把模型带去编造出处。

路由表（`llm/router.py::ROUTING_TABLE`）来自阶段三横向对比结论：

| 任务 | 首选 | 温度 | 依据 |
| --- | --- | --- | --- |
| 事实核查 | anthropic → openai → deepseek | 0.1 | Claude 事实最保守（幻觉率约 10%） |
| 结构化提纲 | openai → deepseek → anthropic | 0.3 | GPT-4o 结构最完整 |
| 逻辑推导 | openai → anthropic | 0.2 | 需"先举反例再下结论" |
| 中文口语化 | qianfan → openai | 0.6 | 文心中文最自然 + 高温缓解同质化 |
| 反同质化生成 | openai → anthropic | 0.9 | 强制多组织方式 |

## 五、离线模型（MockProvider）的设计

它不是"随便返回假文本的桩"，而是一个**可复现的基线模型**：

```text
读提示词 → 识别模块编号 + 话题 + 是否带图片
   ├─ 按模块的分段契约输出：固定段落标题、交叉验证、易错点、超纲标注
   ├─ 遇到幻觉/逻辑陷阱题 → "拒绝编造 + 明确声明无法确认"
   └─ 带图片时 → 如实说明已接收的图片并拒绝推断图片内容（不编造）
```

知识库 `llm/kb.py` 与 `llm/outlines.py` 提供：
- 高等数学极限（洛必达 × 泰勒交叉验证）、多元函数微分学提纲（3 种组织方式）
- 计算机网络 TCP 知识体系（四级分层 + 三张对比表 + 超纲标注）
- 计算机科学递归（查词典类比 + 代码注释 + 调用栈表）
- 幻觉守卫 H1–H6、逻辑纠正 L1–L5 的标准答案

价值：让整套流程在没有 Key、没有网络时也能**自动运行、结果可复现**。
报告与界面均显式标注"离线模拟"，不用于证明任何真实模型性能。

## 六、评测层

### 6.1 用例模型

```python
@dataclass
class RiskCase:
    id, type(hallucination|logic|repetition|comparison), title, question, module
    expectation          期望的正确表现
    risk_flags           正则：命中即视为该类风险发生
    compliant_markers    合规信号（主动声明不确定等）
    expected_conclusion  逻辑题正确结论关键词
    wrong_conclusion     逻辑题错误结论关键词
    plain_prompt         无约束提示原文（消融对照用；不是用户可见的提示词模式）
```

**关于「消融对照」**：应用对外只有精细提示，所以阶段三的"粗放 vs 精细"
在 v1.1.0 起改为评测层的**内部机制**——`_run_case(mode="plain")` 会走
`FeatureContext.plain_prompt=True` 分支，此时 `build_prompt()` 只注入角色与问题，
不注入段落契约、质量红线与诚实边界要求。它用于量化"提示词结构本身"的贡献，
只在 `risk` / `ablate` / `selftest` 内部使用，**界面与 Web API 都不暴露该开关**。

### 6.2 判定器（关键设计）

```text
judge(case, answer):
  逻辑题：detect_flags()（直接匹配）
  幻觉题：_explicit_assertions()  ← 只在"断言语境"下认定编造
           命中的风险模式，其前后 ±80/±160 字符窗口内必须
             ① 出现断言线索（规定/指出/给定/DOI/作者/页码 ...）
             ② 不出现否定线索（不可采信/并不存在/都不予采信 ...）
           → 避免把模型的"纠错引用"误判为幻觉
          （例：「任何关于……不低于总学时 25% 的表述都不可采信」是合规行为）

  conclusion_ok：给出正确结论 → True；只给错误结论 → False
  risk_hit（逻辑题）：conclusion_ok=False → True；True → 强制 False
  compliance：出现合规信号且未发生风险；逻辑题额外允许"结论正确"作为合规信号
```

这套规则解决了三类误判：
1. 模型引述错误说法再纠正 → 误判为逻辑错误
2. 模型说明"该文件不存在 / 数据不可采信" → 误判为幻觉
3. 无约束输出碰巧用词与合规信号相同（如"现行"）→ 误判为合规

### 6.3 量化指标

| 指标 | 计算 |
| --- | --- |
| 事实幻觉出现率 | 出现幻觉的题目数 / 幻觉题数 |
| 逻辑错误率 | 出现逻辑错误的题目数 / 逻辑题数 |
| 合规率 | 出现合规信号的输出占比 |
| 结构完整度 | `quality_check.structure_score` 均值 |
| 不确定标记 | `quality_check.honesty_score` 均值 |
| 教学价值 | `quality_check.teaching_score` 均值 |
| 重复度 | 多次输出两两相似度均值 |
| 通过判定 | 幻觉率 ≤20% 且 逻辑错误 ≤1 处 且 重复度 ≤30% |

### 6.4 相似度算法（`utils.py`）

```text
strip_markup()        去掉表格框线、项目符号、括号，只留语义内容
char 2-gram Jaccard   字符二元组集合交并比（对同义改写敏感）
LCS ratio             最长公共子序列占比（次序保持度，长度裁剪到 1500 保性能）
structure_sim         段落标题集合的交并比
overall = 有结构时 0.5×2gram + 0.3×LCS + 0.2×结构；无结构时 0.6×2gram + 0.4×LCS
```

### 6.5 同质化测试的控制变量设计

阶段三要求"同一任务重复 3 次"。实现上：
- **任务不变**（多元函数微分学期末复习提纲，含概念/题型/易错点）
- **措辞变**（3 种自然表述变体），模拟真实使用中"换个说法问，答案却几乎一样"
- **对照增强**：反同质化组在提示词中显式要求"变换叙述风格 / 至少 2 种组织方式 / 不同框架"

离线模型据此分别返回同一种组织结构（高重复）与三种不同组织结构（低重复），
使指标具备可解释的差异来源。

```sql
sessions(id, title, subject, module, model, created_at, updated_at, meta JSON)

                  answer, mode_detected, flags JSON, provider, model, created_at)
```

设计要点：
- **完整保留提示词原文与输出原文**（阶段三"记录方式"要求）
- WAL 模式 + 单连接线程锁，支持 Web 多线程并发
- JSON 字段透明编解码，调用方直接传 dict/list

## 八、Web 层

- 标准库 `ThreadingHTTPServer`，无框架
- 前端原生 HTML/CSS/JS，**无 CDN、无外部资源**，完全离线可用
- 静态文件服务做路径穿越防护（`Path.resolve().relative_to(STATIC_DIR)`）
- API 与 UI 分离：所有能力都可通过 REST 调用，便于二次开发

## 九、已知取舍与边界

| 取舍 | 说明 |
| --- | --- |
| 质检为规则化近似 | 覆盖不了语义级问题（如推导是否真的正确），仅用于批量筛选，必须配人工复核 |
| 幻觉判定依赖正则 | 用例的风险模式需人工编写；新类型的幻觉要新增模式 |
| 离线模型的知识库有限 | 只覆盖汇报中出现的学科主题；其它问题走通用模板输出，仍满足结构约束但不保证学科准确性 |
| M5/M6 会话状态存 JSON | 简单够用；若要支持大规模并发多轮，建议独立会话状态表 |
| token 统计为估算 | 离线模型用字符估算；真实模型优先使用接口返回的 usage |
| 不包含 PDF/OCR 解析 | 题目需以文本形式提交；如需图片识别题目，属后续阶段工作 |

## 十、如何扩展

**新增一个功能模块（如 M7 实验报告批改）**

1. 在 `prompts/schema.py::STRUCTURE_PATTERNS` 增加结构模式
2. 在 `prompts/modules.py` 定义 `ModuleSpec`（角色/任务/受众/结构模式/红线）
3. 在 `features/` 中继承 `BaseFeature` 实现 `run()`
4. 在 `features/plan.py::FEATURES` 注册，在 `MODULE_KEYWORDS` 补关键词
5. 运行 `python -m ai_tutor selftest` 验证

**新增一个风险用例**

在 `eval/cases.py` 追加 `RiskCase`（含 `risk_flags` 与 `compliant_markers`），
即可自动进入消融对照测试、多工具对比与用例集导出。

**新增一个模型提供方**

在 `llm/` 下继承 `LLMProvider` 实现 `chat()`，在 `registry.py::_build_provider`
注册构造逻辑，在 `config.json` 增加配置项即可。
